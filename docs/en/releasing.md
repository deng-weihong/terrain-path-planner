# Source Snapshots and Releases

[简体中文](../releasing.md) | [English](releasing.md)

## Current Status

The project repository is <https://github.com/deng-weihong/terrain-path-planner>. It contains standalone Python and C++ implementations, the 3D viewer, tests, and documentation in Chinese and English. Chinese is the default documentation language.

The project uses the root [MIT license](../../LICENSE). Source archives include the license, dependency notices, and C++ upstream copyright notices. Dependencies retain their own licenses. Preserve the applicable notices when distributing binaries.

## Create a Source Snapshot

```bash
npm run package:source
```

This produces `releases/terrain-path-planner-0.1.0-source.tar.gz` and a SHA-256 file. The script archives explicitly allowed source, documentation, examples, configuration, and tests. It does not require a Git repository.

Archives exclude:

- Recorded maps and trajectories in `data/local/`.
- Python virtual environments, Node dependencies, and caches.
- Build output, test screenshots, runtime logs, and temporary job results.
- Other modules, configuration, and credentials from the surrounding robot workspace.

Public scenes are generated by code, so an extracted archive works without private map data. Project documentation and selected viewer preview images are included.

## Release Verification

1. Install dependencies in an independently extracted directory, build C++, and run CTest, cross-language regressions, minimal examples, and the frontend build.
2. Run browser checks and inspect desktop and mobile screenshots, maps, routes, and interactions.
3. Compare implementation and limitations with the algorithm documentation. Verify the independent C++ library, CLI, and viewer engine selection.
4. Verify that `LICENSE`, provenance, dependencies, and the release version agree.
5. Check the repository URL and staged contents, then push and create a version.

The Git repository uses `main`. Chinese documentation stays at the default paths, the English homepage is `README.en.md`, and detailed English documents live in `docs/en/`. Validate both languages together when releasing so examples and constraint descriptions remain consistent.
